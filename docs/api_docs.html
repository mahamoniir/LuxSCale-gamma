Internal API Reference

LuxScale API

The lighting-calculation engine behind LuxScale — room-based photometric calculations, IES-driven fixture solutions, study persistence, and PDF report generation. This reference is generated directly from the live route definitions in app.py, so it stays accurate as the backend evolves.

Base URLhttps://web-production-8d09d.up.railway.app
Formatapplication/json
AuthSession cookie or Bearer token (admin routes only)
Every Try it panel below sends a real request to the URL above (defaults to this page's own origin). Point it at your local Flask instance or the deployed API to test live.

Authentication

Most endpoints are public. Routes under /api/admin/* require one of the following:

MethodHow
Session cookieSet automatically after a successful POST /api/admin/login. Works for same-origin browser clients.
Bearer tokenSend header X-Admin-Token: <token>, issued at login. Use this for dashboards hosted on a different origin. Tokens expire after 7 days by default (LUXSCALE_ADMIN_TOKEN_TTL_S).
CORS is restricted to configured origins (LUXSCALE_CORS_ORIGINS). If you're calling this API from a new frontend origin, it needs to be added there first — otherwise browser requests will be blocked before they hit these routes.

Error format

Two shapes are currently in use across the API — handle both when parsing failures:

Shape A — most endpoints
{ "status": "error", "message": "..." }
Shape B — submit validation & report generation
{ "error": "..." }

Calculation

2 endpoints
POST /calculate No auth

Runs the lighting calculation engine for a room and returns fixture placement solutions. Every call is recorded to a calculation trace file, whether it succeeds or fails.

Body parameters
FieldTypeRequiredNotes
sidesarrayRequiredRoom boundary coordinates
heightnumberRequiredCeiling height in meters
placestringConditionalCalculator room-type key. Required if standard_ref_no doesn't resolve.
project_infoobjectOptionalFree-form metadata; standard_ref_no may be nested here
standard_ref_nostringConditionalReference number into the standards table. Required if place isn't given.
fastbool / stringOptionalAlso accepted as query param ?fast=1. Enables faster calc mode.
At least one of place or a valid standard_ref_no is required. If both resolve, the standard row takes priority.
Request
cURL
curl -X POST https://web-production-8d09d.up.railway.app/calculate \
  -H "Content-Type: application/json" \
  -d '{
    "sides": [5, 4, 5, 4],
    "height": 2.8,
    "place": "office_open_plan"
  }'
200success
{
  "status": "success",
  "project_info": { ... },
  "results": [ { ...one object per fixture solution... } ],
  "length": 5,
  "width": 4,
  "calculation_trace_file": "path/to/trace.json",
  "calculation_meta": { ... },
  "ui_settings": { ... },
  "standard_row": { ...only if standard_ref_no resolved... }
}
Errors
400
Body isn't a JSON object
400
Missing sides or height
400
Invalid ceiling height
400
Neither place nor a valid standard_ref_no given
400
Exception during calculation — body includes message and, if available, calculation_trace_file
POST /pdf No auth

Same input contract as /calculate, but streams a generated PDF directly instead of returning JSON.

Body parameters

Identical to /calculate: sides, height, one of place / standard_ref_no, plus optional project_info and fast.

200application/pdf · Content-Disposition: attachment; filename="report.pdf"
400
Missing sides or height
400
Neither place nor standard_ref_no resolvable
Unlike /calculate, this route doesn't wrap calculation in a try/except — an internal error surfaces as a raw 500, not a JSON error body.

Standards

4 endpoints

Two-step selection over standards/standards_cleaned.json (331 rows): pick a category, then a task/activity within it, then read the full row by ref_no. standards/standards_keywords_upgraded.json powers category detection when the room type isn't obvious from a label alone.

GET/api/standards/categoriesNo auth

Every category actually present in the data — category_base alone, or "category_base – category_sub" when a sub-category exists. This is select #1. Each entry includes its ref_no count and any keyword hints available for it.

Studies are saved calculation results retrievable later by token — used for shareable, client-facing results pages. Stored server-side as JSON.

Saves a study payload and returns a retrieval token.

          
Body parameters

          

            
FieldTypeRequiredNotes

heightnumberRequiredMust be > 0 and pass ceiling-height validation

            
resultsarrayRequiredMay be empty, but the key must be present

            
project_name, name, phone, company, email, place, standard_ref_no, standard_category, standard_task_or_activity, standard_lighting, calculation_meta—OptionalPassed through as-is into the stored payload
