Internal API Reference

LuxScale API

The lighting-calculation engine behind LuxScale — room-based photometric calculations, IES-driven fixture solutions, study persistence, PDF report generation, and AI-assisted analysis. This reference is generated from the live route definitions in app.py, luxscale/ai_routes.py, and luxscale/ies_routes.py, so it stays accurate as the backend evolves.

Base URLhttps://web-production-8d09d.up.railway.app
Formatapplication/json  ·  multipart/form-data (IES upload)
AuthSession cookie or Bearer token (admin routes only)
Every Try it panel below sends a live request to the URL above (defaults to this page's own origin). The Admin token is sent as an X-Admin-Token header on every request when set, and persists in sessionStorage for the lifetime of the tab.

Authentication

Most endpoints are public. Routes under /api/admin/* and /api/ai/* require one of the following:

MethodHow
Session cookieSet automatically after a successful POST /api/admin/login. Works for same-origin browser clients.
Bearer tokenSend header X-Admin-Token: <token>, issued at login. Use this for dashboards hosted on a different origin. Tokens expire after 7 days by default (LUXSCALE_ADMIN_TOKEN_TTL_S).
CORS is restricted to configured origins (LUXSCALE_CORS_ORIGINS). If you're calling this API from a new frontend origin, it needs to be added there first — otherwise browser requests will be blocked before they hit these routes.

Error format

Two shapes are currently in use across the API — handle both when parsing failures:

Shape A — most endpoints
{ "status": "error", "message": "..." }
Shape B — submit validation, report generation, IES upload
{ "error": "..." }

Calculation

4 endpoints

The core photometric engine. /calculate is the classic rectangular-room path (4-side geometry). /cad_calc is the new polygon path for arbitrary N-sided rooms. Both return the same result schema so downstream tooling (PDF, AI, storage) can consume them interchangeably.

POST /calculate No auth

Runs the lighting calculation engine for a rectangular room and returns fixture placement solutions. Every call is recorded to a calculation trace file, whether it succeeds or fails.

Body parameters
FieldTypeRequiredNotes
sidesarray[4]RequiredRoom side lengths in meters. Engine uses max(sides[0], sides[2]) as width and max(sides[1], sides[3]) as length.
heightnumberRequiredCeiling height in meters
placestringConditionalCalculator room-type key. Required if standard_ref_no doesn't resolve.
project_infoobjectOptionalFree-form metadata; standard_ref_no may be nested here
standard_ref_nostringConditionalReference number into the standards table. Required if place isn't given.
material_physicsobjectOptionalOptional {irf, label} to override room-reflectance preset for this call
fastbool / stringOptionalAlso accepted as query param ?fast=1. Enables faster calc mode.
At least one of place or a valid standard_ref_no is required. If both resolve, the standard row takes priority.
Request
cURL
curl -X POST https://web-production-8d09d.up.railway.app/calculate \
  -H "Content-Type: application/json" \
  -d '{
    "sides": [6, 4, 6, 4],
    "height": 3.0,
    "place": "Office"
  }'
200success
{
  "status": "success",
  "project_info": { ... },
  "results": [ { ...one object per fixture solution... } ],
  "length": 6,
  "width": 4,
  "calculation_trace_file": "path/to/trace.json",
  "calculation_meta": { ... },
  "ui_settings": { ... },
  "standard_row": { ...only if standard_ref_no resolved... }
}

          POST
          /cad_calc
          No auth
        

        

          
Polygon-based lighting calculation for arbitrary N-sided rooms. Accepts a list of 2D vertices (in meters) and returns the same result shape as /calculate, plus polygon geometry metadata (shoelace area, perimeter, centroid, bounding box, convexity). Ideal for CAD tools that already produce a polygon outline.

          
Phase A behavior: total lumens are correct for any polygon shape (uses shoelace area). Fixture placement in the returned results is still on an equivalent-area rectangular grid — polygon-clipped placement lands in the follow-up phase. See development_plan/06-non-symmetric-rooms-migration-plan.md.


          
Body parameters

          

            
FieldTypeRequiredNotes

            
polygonobject / arrayRequiredOne of: {"vertices": [[x,y],...]}, [[x,y],...], or top-level vertices. Minimum 3 vertices, all coordinates in meters. CW input auto-normalized to CCW.

            
heightnumberRequiredCeiling height (m)

            
placestringConditionalLegacy calculator place key

            
standard_ref_nostringConditionalReference into the standards table (alternative to place)

            
project_infoobjectOptionalPass-through metadata

            
fastboolOptionalSame semantics as /calculate

    "place": "Office"

IES viewer
6 endpoints

      
Stateful photometric-file viewer. Upload an .ies file (or look one up by luminaire name), get a session id back, then use that sid to render the polar curve, raw candela data, 360° panorama, or top-down floorplan heatmap. Sessions live in memory only — restart the server and they're gone.

Uploads an IES file and starts a session. Three input modes:
